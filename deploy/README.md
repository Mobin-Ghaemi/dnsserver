# نصب فعال همین سرور

پنل در `/opt/orbit-dns` و آدرس `https://62.60.211.103` اجرا می‌شود. سورس قابل ویرایش `/root/dnsserver` است. سرویس‌های systemd: `orbit-dns` و `orbit-bind-bridge`. PostgreSQL در کانتینر `orbit-dns-db` با volume مستقل و پورت محلی 15439 نگهداری می‌شود. Gunicorn فقط روی `127.0.0.1:18009` و API رابط BIND فقط روی `127.0.0.1:18081` گوش می‌دهند. Nginx و گواهی مستقل IP، HTTPS را تأمین می‌کنند. تمدید گواهی با تایمر `orbit-ip-certificate.timer` انجام می‌شود؛ پورت ۸۰ برای HTTP challenge باید در دسترس بماند. آدرس قدیمی پنل به IP هدایت می‌شود.

DNS واقعی این میزبان **BIND** است. `bind_bridge.py` زیرمجموعهٔ مورد نیاز API PowerDNS را با کلید خصوصی ارائه می‌کند؛ پنل بدون تعویض سرویس DNS به فایل‌های BIND متصل است. رابط فقط zoneهای static در فایل‌های مشخص `/etc/bind/startup/{zones,customers,orbit}.conf` را مدیریت می‌کند؛ برای BIND با views یا DNSSEC/dynamic update طراحی نشده است. از آن برای واردکردن چنین zoneهایی استفاده نکنید. هر تغییر، بکاپ محلی می‌گیرد، zone و configuration را بررسی و سپس با rndc بارگذاری می‌کند؛ خطای بارگذاری فایل قبلی را برمی‌گرداند. فقط کاربران مورد اعتماد حساب مدیریت دریافت کنند.

آپدیت همین نصب، پس از commit و push کد به upstream، از پوشهٔ سورس:

```bash
cd /root/dnsserver
./deploy/update.sh --host
```

این مسیر از دیتابیس پنل، تنظیمات، BIND و metadata رابط بکاپ می‌گیرد و سپس سرویس‌های نصب native را آپدیت می‌کند. اطلاعات ورود اولیه در `/var/lib/orbit-bind/admin-password` با دسترسی فقط root قرار دارد؛ نام کاربر `admin` است. بعد از تغییر رمز از داخل پنل، این فایل دیگر رمز فعلی نیست.

پیش از اتصال، بکاپ اصلی در `/srv/dns/snapshots/orbit-panel-before` گرفته شده است. سرویس DNS موجود عوض نشده و رکوردهای اصلی هنگام import فقط خوانده می‌شوند. بکاپ رابط در `/var/lib/orbit-bind/backups` است. این مسیرها و دیتابیس PostgreSQL باید در بکاپ خارجی هم باشند.

# نصب و آپدیت وب‌اپ DNS

این مسیر برای Docker Compose v2 روی سرور Linux است. Docker و Compose باید از قبل نصب باشند. دستورات را در پوشهٔ clone پروژه اجرا کنید.

```bash
./deploy/install.sh
# بار اول .env ساخته می‌شود؛ آن را با تنظیمات واقعی ویرایش کنید.
./deploy/install.sh
docker compose exec web python manage.py createsuperuser
```

در `.env` حتماً `DJANGO_DEBUG=False`، کلید تصادفی حداقل ۵۰ کاراکتری، رمز PostgreSQL، نام میزبان پنل، trusted origin با HTTPS و مشخصات API خصوصی PowerDNS را تنظیم کنید. Nginx و TLS را طبق `deploy/nginx.conf` آماده کنید. پنل فقط روی loopback:8000 ارائه می‌شود. داخل کانتینر، `127.0.0.1` خود کانتینر است؛ API روی میزبان باید از یک رابط خصوصی قابل دسترسی باشد یا PowerDNS در شبکهٔ Docker مشترک قرار گیرد. جزئیات اتصال در README اصلی آمده است.

## آپدیت

پس از commit و push نسخهٔ جدید به مخزن upstream:

```bash
./deploy/update.sh
```

اسکریپت با قفل هم‌زمانی، بررسی تمیزبودن checkout و داشتن upstream شروع می‌شود؛ سپس بکاپ دیتابیس پنل، `.env` و commit قبلی را در `backups/` با دسترسی محدود ذخیره می‌کند، `git pull --ff-only` و build را اجرا می‌کند و منتظر سلامت کانتینرها می‌ماند. migration و collectstatic با entrypoint اجرا می‌شوند. اسکریپت‌ها خودکار وابستگی سیستم، Nginx، TLS یا PowerDNS نصب نمی‌کنند. آپدیت ممکن است وقفهٔ کوتاه داشته باشد.

بکاپ PowerDNS جداگانه لازم است. در شکست آپدیت، لاگ‌ها و مسیر بکاپ گزارش می‌شوند؛ rollback خودکار دیتابیس انجام نمی‌شود، چون migration ممکن است برگشت‌پذیر نباشد. برای بازگشت، commit و بکاپ سازگار را با هم بازیابی کنید. بکاپ‌ها را به محل امن خارج از سرور منتقل کنید.

## چهار نیم‌سرور

پیش‌فرض پروژه: `ns1.melkata.ir`، `ns2.melkata.ir`، `ns1.ezfile.ir` و `ns2.ezfile.ir`. NSهای واردشده از PowerDNS حفظ می‌شوند. هر NS اعلام‌شده باید واقعاً پاسخ authoritative سازگار داشته باشد؛ اگر چند سرور دارید، تکثیر آن‌ها جداگانه لازم است.

در «دامنه‌های من ← بررسی اتصال دامنه» نام دامنه را وارد کنید. پاسخ NS از Cloudflare و Google با timeout محدود گرفته می‌شود. حداقل دو NS مجاز، بدون NS خارجی و با پاسخ یکسان در هر دو resolver، تطابق محسوب می‌شود. این بررسی پاسخ recursive و کش‌شده است؛ تأیید مستقیم رجیستری یا اثبات مالکیت نیست. [قرارداد resolver در dnspython](https://dnspython.readthedocs.io/en/stable/resolver-class.html).

برای فهرست دامنه‌های موجود، API PowerDNS را متصل کنید و با مدیر «شناسایی سرور» را بزنید. فهرست تمام دامنه‌ها از NS عمومی قابل استخراج نیست. برای رکورد A ریشه نام `@` و برای زیردامنه `www` یا `app` بگذارید، IPv4 مقصد را وارد و «انتشار تغییرات» را بزنید. NS صحیح به‌تنهایی مالکیت دامنه را برای کاربران اثبات نمی‌کند؛ ساخت حساب کاربران باید توسط مدیر و برای افراد مورد اعتماد باشد.
